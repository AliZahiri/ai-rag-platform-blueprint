# v0.4.2 — GPU Fleet Image Consistency

Status: Released on 2026-11-24.

## Release intent

`v0.4.2` is a patch release that closes a GPU promotion safety gap: a fleet
could previously pass node-level readiness checks while referencing different
model or rollback images. The readiness gate now requires one immutable model
image digest and one distinct immutable rollback image digest across all valid
node observations.

## Highlights

- Mixed model image digests fail the GPU readiness gate with a fleet-level
  violation.
- Mixed rollback image digests fail the GPU readiness gate with a fleet-level
  violation.
- Existing single-node and homogeneous-fleet evidence remains compatible.
- Default validation remains offline and does not call a provider or GPU.

## Compatibility and upgrade notes

- The release-check manifest remains at schema version `1`; no CLI arguments or
  manifest fields changed.
- Operators collecting multi-node readiness evidence must use the same model
  and rollback image digests for every node in a promotion candidate.
- No application-data or database migration is introduced.

## Known limitations

- Digest consistency proves that the candidate images are identical across the
  supplied observations; it does not prove that the live nodes actually run
  those images.
- The gate remains an offline evidence contract and must be paired with live
  health checks and deployment smoke tests.

## Rollback

This patch changes validation behavior only and introduces no data migration.
Operators can pin their checkout to `v0.4.1` while investigating an adoption
issue. Revert or temporarily omit mixed-fleet evidence before re-enabling the
stricter promotion gate only with an explicit operational decision.
