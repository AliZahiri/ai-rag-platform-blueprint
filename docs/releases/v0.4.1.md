# v0.4.1 — Citation Review Date Validation

Status: Released on 2026-11-19.

## Release intent

`v0.4.1` is a patch release that makes citation review-date validation reject
malformed evidence consistently. It does not change the RAG release manifest
or add provider calls to default validation.

## Highlights

- Citation freshness validation now rejects malformed `last_reviewed_at`
  strings with a clear validation error instead of silently ignoring them.
- Source freshness policy treats `datetime` objects as invalid for the date-only
  review field, avoiding invalid freshness calculations.

## Compatibility and upgrade notes

- The release-check manifest remains at schema version `1`; CLI entry points,
  arguments, and manifest fields are unchanged.
- Citation review values must be valid ISO dates in `YYYY-MM-DD` form. Correct
  malformed values before relying on the citation freshness release gate.
- No application-data or database migration is introduced.

## Known limitations

- These checks validate the supplied review-date value and freshness policy;
  they do not establish that a citation's content is authoritative or that the
  referenced source remains accessible.
- The gate's freshness threshold remains caller-configurable. A passing result
  reflects the supplied date and policy, not an independent source review.
