# v0.3.0 — RAG Evidence Coverage and Immutable Compose Defaults

Status: draft release candidate. No `v0.3.0` tag or GitHub Release has been
published.

## Release intent

`v0.3.0` is a proposed minor release of the offline RAG release-control
baseline. It expands the evidence that the unified release check evaluates and
makes the default Compose image selection reproducible through immutable OCI
index digests. Default CI remains provider-free and does not make paid model
or vector-store calls.

## Proposed highlights

- The checked-in release manifest and validation workflow now exercise
  evaluation provenance, bounded evaluation regression, retrieval
  prompt-injection containment, response-safety classification, and fresh
  vector-restore observations in addition to the existing route, citation,
  retention, backup, and replica controls.
- Default Compose image references and the example environment file are pinned
  to reviewed OCI index digests. The offline validator rejects unpinned
  defaults and override drift.
- The release-check runner continues to use schema version `1`, an explicit
  gate allowlist, direct Python execution without a shell, bounded arguments,
  and per-gate timeouts.
- GitHub Actions references are pinned to full commit SHAs, and the existing
  validation workflow runs the complete offline manifest on pushes and pull
  requests.

## Compatibility and upgrade notes

- Existing documented CLI entry points remain available. No runtime data or
  configuration migration is required.
- The manifest schema remains at version `1`. Existing custom manifests remain
  valid when their selected gates and arguments satisfy the v1 contract; the
  checked-in example manifest has expanded coverage.
- Production Compose overrides should use the same digest-pinned convention as
  the defaults. The pinning validator intentionally rejects tag-based or
  mismatched overrides; see [immutable image pinning](../compose-image-pinning.md)
  for the controlled upgrade process.
- This repository is a blueprint and its passing sample evidence does not
  authorize a live deployment. Operators must substitute reviewed evidence and
  retain the aggregate release report with their own release artifacts.

## Known limitations

- Release gates validate supplied configuration and evidence. They do not prove
  that a live evidence collector, model provider, vector store, or source
  system is healthy or trustworthy.
- The example evidence is deterministic and intentionally provider-free. Live
  probes remain opt-in, credential-scoped operator actions.
- An OCI digest identifies an image artifact but does not replace upstream
  advisory review, signature verification, registry controls, or a rollback
  plan.

## Candidate validation

Run these checks from a clean checkout of the candidate commit:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests
python3 scripts/rag_release_check.py examples/release-checks.example.json
python3 -m json.tool examples/release-checks.example.json >/dev/null
python3 -m json.tool schemas/rag-release-check-manifest.v1.schema.json >/dev/null
python3 scripts/compose_image_pinning.py \
  --compose compose/docker-compose.yml \
  --env env/.env.example \
  --json
git diff --check v0.2.0...HEAD
```

Expected results:

- all unit tests pass;
- the aggregate release report has `status: "pass"` with every shipped gate
  passing;
- the manifest and schema parse as JSON;
- Compose defaults and the example environment resolve to the same immutable
  digests; and
- the release diff has no whitespace errors.

## Rollback

This proposed release changes offline validation, documentation, and default
image-selection policy; it does not migrate runtime data. A downstream user can
pin to `v0.2.0` while investigating an adoption issue. For a digest upgrade
problem, restore the previously reviewed digest in both
`compose/docker-compose.yml` and `env/.env.example`, then rerun the pinning
validator and release checks. Do not bypass a failing policy gate to complete a
rollback.
